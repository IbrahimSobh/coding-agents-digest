# Coding agents update

**Oct 14 to Oct 21, 2026** · Claude Code, Antigravity CLI, Codex CLI, Cline, Kilo Code · 22 releases, 456 bug fixes

## In one minute

- **Claude Code** had a heavy week (9 releases, 363 fixes). The big changes: MCP permission rules now match only the exact server, idle conversations compact themselves before the cache expires, and `/auto-mode-setup` teaches auto mode about your project.
- **Antigravity CLI** added Auto mode and a `/compact` command, and rebuilt `agy plugin validate` with `--strict` and `--json` for CI.
- **Codex CLI** 0.163.0: searchable `/config`, steering Codex with follow-up messages mid-answer, and parallel read-only tools.
- **Cline** started a gradual rollout of Cline Cloud sessions. **Kilo Code** redesigned the Agent Manager worktree dialog and added `kilo auto` router commands.
- **Shared theme: agents that do more without asking, with a safety reviewer in front.** agy got Auto mode with a separate review agent, and Claude Code got a guided setup and a model setting for its auto mode classifier. The same week, Claude Code, agy and Cline all added automatic retries for broken streams or tool calls.

## ⚠️ Action needed

- **Claude Code: MCP allow rules are stricter** ([2.1.299](https://github.com/anthropics/claude-code/releases/tag/v2.1.299)). A rule `mcp__a` no longer allows a server named `a__b` or `a_`. Write `mcp__<server>__*` with the full server name. Agent `tools:` lists follow the same rule. Check your allow rules, or tools you expect to run will start asking.
- **Claude Code: `claude remote-control --sandbox` / `--no-sandbox` removed** ([2.1.300](https://github.com/anthropics/claude-code/releases/tag/v2.1.300)). Passing either flag now exits with an error. Use `sandbox.enabled` in settings.
- **Claude Code: hook `updatedInput` is now validated** ([2.1.300](https://github.com/anthropics/claude-code/releases/tag/v2.1.300)). For PreToolUse and PermissionRequest hooks, unknown keys are dropped and input the tool rejects denies the call. Test hooks that rewrite tool input.
- **Claude Code: `allowedMcpServers` filters less** ([2.1.305](https://github.com/anthropics/claude-code/releases/tag/v2.1.305)). `managed-mcp.json` stdio servers that use `${VAR}` only in `env` are no longer filtered, so a server your allowlist left out can load on upgrade. Admins: add it to `deniedMcpServers` to keep it off.
- **Claude Code: Claude Design closes on December 14, 2026** ([2.1.302](https://github.com/anthropics/claude-code/releases/tag/v2.1.302)). `/design-sync` and `/design-login` now show this notice for standalone Claude Design (claude.ai/design).
- **Cline CLI: `CLINE_PLUGIN_MODE=in_process` is no longer supported** ([cli-v3.0.72](https://github.com/cline/cline/releases/tag/cli-v3.0.72)). Plugins run in a worker now. Use `worker` (the default) or `sandbox`.
- **Cline: OpenAI Compatible base URLs are used exactly as typed** ([v4.1.25](https://github.com/cline/cline/releases/tag/v4.1.25)). A host-only URL like `https://abc.com` no longer gets `/v1` added. URLs saved by older versions get `/v1` added once. If you add a new host-only URL, type the `/v1` yourself if your server needs it.
- **Codex CLI: bundled patched `zsh` is gone** ([0.163.0](https://github.com/openai/codex/releases/tag/rust-v0.163.0)). Codex uses its standard shell executor. Configs that use the retired shell flags get a migration notice.

## Claude Code · 2.1.299 to 2.1.307 · 9 releases, 363 bug fixes

### Idle compaction (2.1.299, 2.1.302)
**What:** In the terminal, a conversation over 200K tokens that sits idle for about 54 minutes is compacted before its one-hour prompt cache expires.

**Why it matters:** When you come back, your next message does not reprocess the whole long conversation. That saves time and usage.

**When to use:** It is on by default. Turn it off if you want the full history kept as is after long breaks.

**Example:** Change the minimum with `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, turn it off with `"idleCompaction": false` in settings.json, or use the new `Idle compaction` row in `/config`.

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.299)

### `/auto-mode-setup` and a model for the auto mode classifier (2.1.304, 2.1.302)
**What:** `/auto-mode-setup` is a guided setup that reads your project and recent sessions to teach auto mode about your environment. `CLAUDE_CODE_AUTO_MODE_MODEL` picks the model the client-side auto mode classifier uses.

**Why it matters:** Auto mode makes fewer wrong calls when it knows your setup. It now also works on Bedrock, Vertex, Foundry, Claude apps gateway and telemetry-disabled sessions.

**When to use:** When auto mode blocks normal commands in your project, or asks too often.

**Example:** Run `/auto-mode-setup` in the project folder. The classifier model setting does not change server-side auto mode.

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.304)

### Fork subagents on by default in `claude -p` and the Agent SDK (2.1.302)
**What:** Fork subagents (`subagent_type: "fork"`) are now on by default in `claude -p`, the Agent SDK, the desktop app and VS Code, as in the terminal. In the desktop app and VS Code, the main conversation's subagents always run in the background.

**Why it matters:** Scripts and SDK apps can now get forks without extra setup. Behavior of existing headless runs can change.

**When to use:** Keep it if you run parallel tasks. Turn it off for strictly linear scripts.

**Example:** `CLAUDE_CODE_FORK_SUBAGENT=0` turns forks off. In the same release, `claude -p` and SDK sessions with no permission mode start in `default` mode on third-party providers; `--permission-mode auto` keeps auto.

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.302)

### `/usage` warnings that fix themselves (2.1.299, 2.1.305)
**What:** `/usage` now warns about max effort, workflows, always-on context and large tool results. Each warning is a one-line fix that names its source, and `f` applies the fixes.

**Why it matters:** You can see what eats your Pro/Max limit and fix it in one key press. The same fixes show in VS Code and `/doctor`.

**When to use:** When you hit usage limits sooner than you expect.

**Example:** Run `/usage`, read the warnings, press `f`.

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.305)

### Safety events in OpenTelemetry (2.1.307, 2.1.301)
**What:** A new `claude_code.safety_event` event fires for each tool call that a permission rule, auto mode, a safety check, a hook or the sandbox stopped, prompted or sent back. `tool_decision` events now carry `classifier_verdict` and `permission_mode`.

**Why it matters:** Teams can see in their dashboards why tool calls were blocked, and tell auto mode decisions apart from permission rules.

**When to use:** If you already export Claude Code telemetry.

**Example:** Set `OTEL_LOG_TOOL_DETAILS=1` to also get `classifier_category` (the built-in rule a classifier block matched).

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.307)

### Warning before an expensive resume (2.1.304)
**What:** On Pro and Max plans, Claude Code warns you when resuming an inactive conversation would use a noticeable share of your 5-hour usage limit.

**Why it matters:** Resuming a big, cold conversation can cost a lot. You now choose: resume anyway, or start a new conversation and let Claude look up the old one when you refer to it.

**When to use:** Any time you resume old sessions.

**Example:** No setting needed; the choice appears on resume.

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.304)

### Retries for broken tool calls (2.1.307)
**What:** When Claude produces a tool call that cannot be parsed, Claude Code retries it up to twice before ending the turn with an error.

**Why it matters:** Fewer long runs die on one bad tool call.

**When to use:** Automatic.

**Example:** No setting.

[Source](https://github.com/anthropics/claude-code/releases/tag/v2.1.307)

## Antigravity CLI · 1.3.5 to 1.4.4 · 7 releases, 49 bug fixes

### Auto mode (1.3.5, extended in 1.3.6, 1.4.3, 1.4.4)
**What:** A new mode that approves file edits and safe commands without asking, and still asks before irreversible actions. Commands that would leave the terminal sandbox are first reviewed by a separate agent.

**Why it matters:** Fewer prompts in normal work, with a reviewer for risky commands. Later releases made the review faster (1.3.6), applied it to subagents and custom agents (1.4.3), checked every subcommand in pipelines (1.4.4), and added Windows 11 24H2+ for personal Google Accounts (1.4.4).

**When to use:** Long tasks where you trust the workspace. `Agent` stays the default mode.

**Example:** Start agy with `--mode auto` (verify), or pick `Agent Mode` in `/config`, or press `Shift+Tab` to cycle modes.

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.3.5)

### `/compact` command (1.3.5)
**What:** Compacts the conversation on demand to free the context window.

**Why it matters:** You control when to summarize, instead of waiting for automatic compaction. It shows how many steps were summarized and how much smaller the context got.

**When to use:** Before starting a new sub-task in a long session.

**Example:** `/compact` summarizes and ends the turn. `/compact <message>` summarizes, then answers your message. Press `Esc` to cancel.

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.3.5)

### `agy plugin validate` rebuilt for CI (1.4.0, 1.4.1, 1.4.3, 1.4.4)
**What:** The validator now uses the same rules the CLI uses to load a plugin. It reports each error and warning with file and line, and checks skills, subagents, rules, hooks, sidecars and MCP configs.

**Why it matters:** The old checks rejected valid plugins and missed real problems. It also warns about a Claude Code-style top-level `"hooks"` key, useful if you port plugins between tools.

**When to use:** In the CI of any plugin you publish.

**Example:** `agy plugin validate --strict --json` (`--strict` fails on warnings, `--json` gives a machine-readable report).

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.4.0)

### `/diff` grows up (1.3.5, 1.4.3, 1.4.4)
**What:** Syntax highlighting, folding, whole-file view and search in the `/diff` file view.

**Why it matters:** Reviewing the agent's changes inside the terminal is now practical, even on big files.

**When to use:** Before you commit agent work.

**Example:** `Ctrl+O` expands or folds a hunk, `f` toggles changes-only vs whole file, `/` searches, `n`/`N` step through matches.

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.4.3)

### Terminal status in the tab title (1.4.0)
**What:** In terminals that support OSC 7501, the tab or window shows whether the CLI is working, waiting for you, done, or failed.

**Why it matters:** You can run agy in a background tab and see when it needs you.

**When to use:** If you run several sessions in tabs.

**Example:** `AGY_CLI_OSC7501=off` turns it off; `AGY_CLI_OSC7501=on` forces it; `AGY_CLI_OSC7501_MESSAGES=brief` hides details.

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.4.0)

### Claude Opus 5.5 and Sonnet 5.5 via Google Cloud (1.3.6)
**What:** Claude Opus 5.5 and Claude Sonnet 5.5 are available when you sign in with Application Default Credentials (`AGY_ADC_AUTH`).

**Why it matters:** Business users can use Claude models in agy through their Google Cloud project.

**When to use:** If your Google Cloud project has access to those models; they only appear in `/model` then.

**Example:** Sign in with `AGY_ADC_AUTH`, then pick the model in `/model`.

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.3.6)

### No more hangs on stalled connections (1.3.6, 1.4.1)
**What:** If no data arrives for 5 minutes, the request is canceled and retried. Socket errors after laptop sleep or a Wi-Fi change are retried instead of ending the turn.

**Why it matters:** Long unattended runs no longer hang forever or die on a short network drop.

**When to use:** Automatic.

**Example:** No setting. Also: agent shell commands now get `GIT_EDITOR=false`, so `git commit` without `-m` fails fast instead of hanging.

[Source](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.3.6)

## Cline · v4.1.25, cli-v3.0.72, cli-v3.0.73 · 3 releases, 9 bug fixes

### Cline Cloud sessions (v4.1.25)
**What:** Run a task in a hosted sandbox on a GitHub repo and branch you choose. It is rolling out gradually.

**Why it matters:** Long tasks can run without your machine, like cloud agents in other tools.

**When to use:** For tasks you want to start and check later.

**Example:** Enable it in Settings (the exact setting name is not in the notes; verify).

[Source](https://github.com/cline/cline/releases/tag/v4.1.25)

### Retry when a stream breaks (v4.1.25, cli-v3.0.72)
**What:** When a provider error interrupts a response mid-stream, Cline retries up to 3 times before failing the turn. The CLI also logs the provider's request id for failed requests.

**Why it matters:** Fewer lost turns on flaky providers, and better data for support tickets.

**When to use:** Automatic.

**Example:** No setting.

[Source](https://github.com/cline/cline/releases/tag/cli-v3.0.72)

### GPT-6 works on OpenAI-compatible endpoints in the CLI (cli-v3.0.73)
**What:** Cline sent `max_tokens` instead of `max_completion_tokens`, so every GPT-6 request (including `gpt-6-sol` and `gpt-6.1-sol`) on OpenAI and Azure OpenAI-compatible endpoints was rejected. Fixed.

**Why it matters:** This fix unblocks GPT-6 models in the Cline CLI.

**When to use:** If you run GPT-6 through OpenAI or Azure endpoints.

**Example:** Update to cli-v3.0.73.

[Source](https://github.com/cline/cline/releases/tag/cli-v3.0.73)

### New `cline hub` flags (cli-v3.0.72)
**What:** `cline hub ensure` and `cline hub start` add `--json`, `--allow-port-fallback`, `--no-connectors` and `--login-shell-path`. `cline hub` adds `--discovery-path`.

**Why it matters:** Easier to script the hub in CI or wrappers.

**When to use:** If you automate the Cline CLI.

**Example:** `cline hub start --json --allow-port-fallback`

[Source](https://github.com/cline/cline/releases/tag/cli-v3.0.72)

Note: the default model of the Cline provider (when you pick none) moved to Gemini 4 Argon in v4.1.25 and cli-v3.0.72, then back to Claude Sonnet 5.5 in cli-v3.0.73. Pick a model explicitly if you want stable behavior.
