# Claude Code 2.1.327 changes auto-mode allow rules and shell startup timing, and Codex 0.170.0 adds realtime WebRTC voice.

## 1. Permission and sandbox holes closed
Claude Code 2.1.323 and 2.1.325 close a Bash `rm` check that could be skipped and a zstd decoding issue ([v2.1.323](https://github.com/anthropics/claude-code/releases/tag/v2.1.323), [v2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)). Antigravity CLI 1.5.7 to 1.5.9 close a hook path that could skip admin review, a sandbox proxy bypass, and a leak of MCP headers after a redirect ([1.5.7](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.7), [1.5.8](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.8), [1.5.9](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.9)). Codex 0.170.0 keeps sandbox restrictions through permission updates and child threads ([rust-v0.170.0](https://github.com/openai/codex/releases/tag/rust-v0.170.0)).

**So what:** update Claude Code to 2.1.327 and Antigravity CLI to 1.5.10 or later.

## 2. Unattended runs now need explicit trust
Claude Code 2.1.325 makes scheduled tasks and `/loop` ask before running a skill with `allowed-tools` or hooks, and sandboxed Bash asks by default ([v2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)). Claude Code 2.1.327 makes `claude mcp add --scope project` stop on a `.mcp.json` whose servers sit at the top level ([v2.1.327](https://github.com/anthropics/claude-code/releases/tag/v2.1.327)), and Codex 0.169.0 keeps project config and MCP servers off in untrusted directories for `codex exec` unless `--trust` is passed ([rust-v0.169.0](https://github.com/openai/codex/releases/tag/rust-v0.169.0)).

**So what:** add `Skill(name)`, the `sandbox.autoAllowBashIfSandboxed` setting, `--trust` and `accept-edits` to unattended jobs, or they may wait for approval or lose their config.

## 3. New defaults change sandbox and shell behavior
Claude Code 2.1.326 stops sandboxed commands from writing to some sensitive home folders by default, and Antigravity CLI 1.5.10 blocks sandboxed reads of `~/.config` by default ([v2.1.326](https://github.com/anthropics/claude-code/releases/tag/v2.1.326), [1.5.10](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.10)). Claude Code 2.1.327 lets shell startup files run before a Bash command is approved ([v2.1.327](https://github.com/anthropics/claude-code/releases/tag/v2.1.327)), and Antigravity CLI 1.5.7 makes Auto the default Agent Mode ([1.5.7](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.7)).

**So what:** re-check sandboxed jobs for blocked paths, and set `CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1` if startup files must wait for approval.

## Action needed at the time
- **Auto is now the default Agent Mode** (Antigravity CLI [1.5.7](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.7)): set `Agent Mode` back to Default in `/config` (this saves `"agentMode": ""` to `settings.json`) if your jobs need the old behavior.
- **Admin review bypass closed** (Antigravity CLI [1.5.7](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.7)): update Antigravity CLI to 1.5.7 or later.
- **Terminal sandbox proxy path bypass fixed** (Antigravity CLI [1.5.8](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.8)): update Antigravity CLI to 1.5.8 or later.
- **Windows command rules need an exact match** (Antigravity CLI [1.5.8](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.8)): write each command as its own rule, or expect approval prompts again.
- **Security fix in zstd response decoding** (Claude Code [2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)): update Claude Code to 2.1.325 or later.
- **Sandboxed Bash asks for permission by default** (Claude Code [2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)): set `sandbox.autoAllowBashIfSandboxed: true` to keep them running without prompts.
- **Scheduled tasks and `/loop` ask before some skills** (Claude Code [2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)): add `Skill(name)` to `permissions.allow` so those skills run unattended.
- **`codex exec` needs `--trust` for project config** (Codex CLI [rust-v0.169.0](https://github.com/openai/codex/releases/tag/rust-v0.169.0)): add `--trust` to those `codex exec` runs.
- **HTTP MCP headers stay on their own server** (Antigravity CLI [1.5.9](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.9)): update Antigravity CLI to 1.5.9 or later.
- **Hook decision block holds in more cases** (Claude Code [2.1.326](https://github.com/anthropics/claude-code/releases/tag/v2.1.326)): remove the block output from those hooks, or make them block only the calls they mean to stop.
- **Sandbox blocks writes to some home folders** (Claude Code [2.1.326](https://github.com/anthropics/claude-code/releases/tag/v2.1.326)): add the folder to `sandbox.filesystem.allowWrite` in user or managed settings.
- **Remote agent asks before each edit** (Antigravity CLI [1.5.10](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.10)): press `Shift+Tab` to switch to `accept-edits`, or edits will wait for approval.
- **Sandbox blocks reads of ~/.config** (Antigravity CLI [1.5.10](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.10)): allow the path the command needs in your sandbox rules.
- **`mcp add` stops on a top-level `.mcp.json`** (Claude Code [2.1.327](https://github.com/anthropics/claude-code/releases/tag/v2.1.327)): move the servers under an `mcpServers` key in `.mcp.json` before the command runs.
- **Auto mode ignores broad allow rules** (Claude Code [2.1.327](https://github.com/anthropics/claude-code/releases/tag/v2.1.327)): run the job once in auto mode and add an exact rule for each command it still asks about.
- **Shell startup files run before approval** (Claude Code [2.1.327](https://github.com/anthropics/claude-code/releases/tag/v2.1.327)): set `CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1` to keep startup files from running before approval.
